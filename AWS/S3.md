# Amazon S3

## What is Amazon S3?

Amazon Simple Storage Service (S3) is an object storage service used to store and retrieve data from anywhere over the internet.

S3 is commonly used for:

* Images and videos
* Documents and files
* Application assets
* Backups
* Logs
* Static websites
* Data lakes

---

## S3 Bucket

A **bucket** is a container used to store objects in S3.

Example:

```text
S3 Bucket
   |
   ├── images/
   ├── documents/
   ├── backups/
   └── logs/
```

Bucket names must be globally unique across AWS.

---

## S3 Objects

An object is a piece of data stored inside an S3 bucket.

An object consists of:

* Data
* Object key (name/path)
* Metadata
* Optional tags

Example:

```text
Bucket: sheepeye-assets

Object:
images/logo.png
```

The object key is:

```text
images/logo.png
```

---

## S3 Storage Classes

S3 provides different storage classes depending on how frequently data is accessed.

### S3 Standard

Used for frequently accessed data.

Examples:

* Website assets
* Application files
* Frequently accessed images

### S3 Intelligent-Tiering

Automatically moves objects between access tiers based on usage.

Useful when access patterns are unpredictable.

### S3 Standard-IA

Designed for data that is accessed less frequently but still needs quick access when required.

### S3 One Zone-IA

Stores data in a single Availability Zone.

Useful for data that can be recreated and does not require multi-AZ storage.

### S3 Glacier

Designed for long-term archival and infrequently accessed data.

Common options include:

* Glacier Instant Retrieval
* Glacier Flexible Retrieval
* Glacier Deep Archive

---

## S3 Durability and Availability

S3 is designed for very high durability.

AWS stores S3 data redundantly across multiple facilities within an AWS Region.

**Durability** refers to how unlikely it is for data to be lost.

**Availability** refers to how accessible the data is when requested.

---

## S3 Versioning

Versioning keeps multiple versions of an object.

Example:

```text
logo.png
   |
   ├── Version 1
   ├── Version 2
   └── Version 3
```

Versioning can help recover objects that were accidentally deleted or overwritten.

It is commonly useful for:

* Data protection
* Accidental deletion recovery
* Maintaining previous versions

---

## S3 Lifecycle Rules

Lifecycle rules automatically transition or delete objects based on conditions.

Example:

```text
Day 0
  ↓
S3 Standard

After 30 days
  ↓
S3 Standard-IA

After 90 days
  ↓
S3 Glacier

After 365 days
  ↓
Delete
```

Lifecycle rules can help reduce storage costs.

---

## S3 Encryption

S3 supports encryption to protect stored data.

### Server-Side Encryption

AWS encrypts objects when they are stored.

Common options include:

* SSE-S3
* SSE-KMS
* SSE-C

For most AWS workloads, SSE-S3 or SSE-KMS are commonly used.

### Client-Side Encryption

The application encrypts the data before uploading it to S3.

---

## S3 Bucket Policy

A bucket policy is a resource-based policy attached to an S3 bucket.

It can control who can access objects in the bucket and what actions they can perform.

Example actions:

```text
s3:GetObject
s3:PutObject
s3:DeleteObject
```

A bucket policy can allow or deny access based on users, roles, accounts, IP addresses, or other conditions.

---

## IAM and S3

IAM policies can also control access to S3.

Example:

```text
IAM Role
   |
IAM Policy
   |
S3 Bucket
```

An EC2 instance can use an IAM role to access an S3 bucket without storing AWS access keys on the server.

---

## S3 Block Public Access

S3 provides **Block Public Access** settings to help prevent accidental public exposure of data.

For private application data, Block Public Access should generally remain enabled unless there is a specific reason to allow public access.

---

## S3 Static Website Hosting

S3 can host static websites containing files such as:

* HTML
* CSS
* JavaScript
* Images

Example:

```text
User
  ↓
S3
  ↓
HTML / CSS / JavaScript
```

For production architectures, CloudFront is often placed in front of S3 to provide content delivery and additional security features.

---

## S3 and CloudFront

A common architecture is:

```text
User
  ↓
CloudFront
  ↓
S3 Bucket
  ↓
Static Content
```

CloudFront caches content closer to users, reducing latency and reducing direct requests to S3.

---

## S3 Presigned URLs

A presigned URL provides temporary access to an S3 object without making the entire bucket public.

Example use case:

```text
Application
     |
Generate Presigned URL
     |
     ↓
User
     |
Download private file
```

Presigned URLs can have an expiration time.

---

## S3 Access Logging and Monitoring

S3 can be integrated with AWS monitoring and logging services.

Common services include:

* CloudTrail
* CloudWatch
* S3 access logging

CloudTrail can help track API activity such as object and bucket operations.

---

## S3 and Sheepeye

S3 could be used in the Sheepeye project for storing objects such as:

```text
S3 Bucket
   |
   ├── car-images/
   ├── service-images/
   ├── documents/
   └── backups/
```

The application can access S3 using an IAM role instead of storing AWS access keys inside the application.

## Important S3 Concepts

| Concept             | Purpose                                   |
| ------------------- | ----------------------------------------- |
| Bucket              | Container for objects                     |
| Object              | Data stored in S3                         |
| Storage Class       | Determines storage/access characteristics |
| Versioning          | Keeps previous object versions            |
| Lifecycle           | Automates transitions/deletion            |
| Encryption          | Protects stored data                      |
| Bucket Policy       | Controls bucket access                    |
| IAM Policy          | Controls AWS identity permissions         |
| Block Public Access | Helps prevent accidental public access    |
| Presigned URL       | Temporary access to private objects       |
| CloudFront          | Delivers S3 content globally              |

---

## Key Points

* S3 is an **object storage** service.
* Data is stored as objects inside buckets.
* Bucket names are globally unique.
* S3 supports multiple storage classes.
* Versioning helps protect against accidental deletion or overwriting.
* Lifecycle rules can automatically transition or delete objects.
* S3 supports encryption.
* IAM and bucket policies control access.
* Block Public Access helps prevent accidental public exposure.
* Presigned URLs provide temporary access to private objects.
* CloudFront can be used with S3 for content delivery.
